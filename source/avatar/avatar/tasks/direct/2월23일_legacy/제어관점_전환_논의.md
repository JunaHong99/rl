# Dual-Arm Transport: 플래닝 관점 → 제어 관점 전환 논의

## 1. 현재 작업 진단

### 1.1 현재 접근법 (`2월23일/`)
- **TD3 + GNN**으로 14-dim joint velocity를 직접 출력
- 두 팔의 상대 자세 제약을 **reward shaping**(`r_constraint`)으로 soft하게 유도
- Velocity control (`set_joint_velocity_target`, `scaling_factor=0.3`)
- 학습은 base run → finetune → finetune2 → finetune3로 반복 진행 중

### 1.2 한계
- 정책이 "task 달성"과 "기하 커플링 유지"를 reward만으로 동시에 학습 → sample efficiency 저하
- `safety_filter.py`(Jacobian projection)는 구현되어 있으나 학습 시엔 OFF, 테스트만 ON
  → **train/test dynamics mismatch** 위험
- 결과: fine-tuning을 3차까지 반복해도 성능 한계 (현재 finetune3, ~115k step)

## 2. 개념 정리

### 2.1 Safety Filter vs Impedance Control (직교적 도구)

| 개념 | 작동 방식 | 역할 |
|---|---|---|
| **Safety filter** | 명령(action)을 제약 만족 집합으로 **사영(projection)** | 운동학·기하학 레벨의 하드 제약 강제 |
| **Impedance control** | $F = M\ddot{x} + D\ddot{x} + K\Delta x$ 동역학 관계 부여 | 로봇을 가상 mass-spring-damper로 동작시킴 (접촉/힘 조절) |

→ 두 개념은 별개. "제어 관점 접근"의 본질은 **constraint를 dynamics에 새겨넣는 것**.

### 2.2 Wrench vs Torque

- **Joint torque ($\tau$)**: 관절 축 회전력. 7-dim 스칼라 벡터.
- **Wrench ($w$)**: 한 점에서의 6D 힘/모멘트 = $[F_x, F_y, F_z, M_x, M_y, M_z]$.
- 관계: $\tau = J^T w$

### 2.3 Internal Wrench (cooperative manipulation 핵심)

두 팔이 공유 객체를 들 때:

$$w_{ext} = w_1 + w_2 \quad \text{(객체를 움직이는 외부 wrench)}$$

$$w_{int} = \frac{1}{2}(w_1 - w_2) \quad \text{(객체 내부 응력 = squeeze)}$$

- $w_{int}$는 객체 가속도에 기여하지 않음
- **제약 위반의 직접적 물리 측정값**이 됨
- Cooperative impedance control의 regulate 대상

### 2.4 Isaac Sim에서 Contact Force 측정

```python
from isaaclab.sensors import ContactSensorCfg

contact_sensor_1 = ContactSensorCfg(
    prim_path="/World/envs/env_.*/Robot_1/panda_hand",
    filter_prim_paths_expr=["/World/envs/env_.*/rod"],  # 특정 쌍만 필터
    update_period=0.0,
    history_length=1,
)
# data.net_forces_w: 모든 접촉의 누적 합 [num_envs, num_bodies, 3]
# data.force_matrix_w: filter_prim과의 force breakdown
```

- **Force만 제공, Moment는 직접 계산** ($M = r \times F$)
- 정확한 6D wrench가 필요하면 `body_link_incoming_joint_force` (articulation 내부 link wrench)
- Contact force는 **두 강체(그리퍼-객체) 사이의 상호작용력**

## 3. 핵심 통찰: 현재 셋업의 본질적 한계

### 3.1 두 팔이 물리적으로 연결되어 있지 않음
- 측정 가능한 joint torque는 대부분 **중력/관성/마찰 보상 토크**
- 제약 위반에서 발생하는 토크가 아님
- **State에 torque를 추가해도 "제약 위반" 신호로 기능하지 못함**

### 3.2 해결: 두 팔을 물리적으로 결합
1. **공유 강체(rod/object)를 들게 함** ⭐ 가장 자연스러움
2. **가상 커플링(virtual rigid bar)** 추가
3. → Cooperative manipulation 문제로 재정의 (Schneider & Cannon, Caccavale 계보)

---

## 4. 접근 방식 비교

### 4.1 RL/제어 분담 가능한 방향들

| 방향 | 설명 | 변경 폭 | 장점 |
|---|---|---|---|
| **(A) Safety filter ON** | 학습 시에도 projection 적용, RL은 그 위에서 학습 | 작음 | hard constraint 보장, 빠른 검증 |
| **(B) Impedance baseline + Residual RL** | 가상 spring-damper가 constraint 잡고, RL은 보정만 | 중간 | reward 설계 단순화 |
| **(C) Cooperative Impedance + Object-level RL** ⭐ | 공유 객체 도입, RL은 객체 목표만 출력 | 큼 | 패러다임 전환, 논문 narrative 명확 |
| **(D) Constrained RL (CPO/Lagrangian)** | 제약을 별도 비용함수로 | 중간 | 이론적으로 깔끔 |

### 4.2 모델 출력 비교

| Option | 출력 | dim | RL 학습 부담 | Controller 역할 |
|---|---|---|---|---|
| **현재** | joint velocity | 14 | 동역학 + 제약 + task | 거의 없음 |
| **A. Joint torque** | $\tau_1, \tau_2$ | 14 | 모든 것 (가장 어려움) | 거의 없음 |
| **B. Task-space target** | $x^d_1, x^d_2$ | 12~24 | 양 팔 좌표 | impedance 추종 |
| **C. Object-level** ⭐ | $x^d_{obj}$ (+$w^d_{int}$) | 6~12 | "물체를 어디로" | 양 팔 분배 + 제약 유지 |
| **D. Residual** | $\Delta\tau$ or $\Delta x$ | 14 | 보정량만 | base impedance 전부 |

## 5. 추천안: Option C (Cooperative Impedance + Object-level RL)

### 5.1 데이터 흐름
```
Actor → [x^d_obj (6), w^d_internal (6, optional)]
         │
         ▼
Cooperative impedance controller
  - object pose error → external wrench (양 팔에 분배)
  - desired internal wrench → grip force
  - 양 팔 jacobian으로 joint torque 계산
         │
         ▼
set_joint_effort_target(τ_1, τ_2)
```

### 5.2 왜 깔끔한가
1. **제약 자동 만족**: 객체가 강체이므로 두 EE 상대 자세는 객체에 의해 정의됨 → `r_constraint`를 reward에서 거의 제거 가능
2. **Action dim 축소**: 14 → 6
3. **물리적 의미 명확**: 객체 운반(task)과 grip force(internal)가 분해 (Khatib augmented object)
4. **Force feedback의 진짜 활용**: contact force가 grip force 조절에 직접 쓰임

### 5.3 구현 변경 사항

#### (1) `dual_arm_transport_cfg.py`
- 공유 막대(rod) `RigidObject` 추가
- 양 그리퍼-막대 사이 fixed joint (학습 단순화) 또는 high friction + closed gripper
- `ImplicitActuatorCfg` → effort(torque) 모드로 변경

#### (2) `_apply_action` (의사코드)
```python
def _apply_action(self):
    x_d_obj = self.actions[:, :6]
    w_d_int = self.actions[:, 6:12] if has_internal else default

    # Cooperative impedance law
    w_ext = K_obj * (x_d_obj - x_obj_curr) - D_obj * x_obj_vel
    w_1 = 0.5 * w_ext + w_d_int
    w_2 = 0.5 * w_ext - w_d_int

    tau_1 = J_1.T @ w_1 + gravity_comp_1
    tau_2 = J_2.T @ w_2 + gravity_comp_2

    self.robot_1.set_joint_effort_target(tau_1, ...)
    self.robot_2.set_joint_effort_target(tau_2, ...)
```

#### (3) `_get_observations`
- `ContactSensor` 추가 → contact force를 graph node 또는 global feature로 주입
- 6D wrench 사용 시 `body_link_incoming_joint_force`도 옵션

#### (4) Reward
- `r_constraint` → 거의 0 (객체 강성이 보장)
- `r_object_pose` 추가 (객체를 목표 자세로 운반)
- 선택: `r_grip` (internal wrench norm regulation)

#### (5) GNN action head
- 출력 차원 14 → 6 (또는 12)
- **출력 위치 변경**: "각 로봇 노드마다 action" → "object 노드 하나의 action"
- Graph에 object 노드를 새로 추가하고 그 출력만 사용

## 6. 단계적 마이그레이션 경로

### Step 1 — 빠른 검증 (변경 최소)
- 현재 코드 그대로 + `safety_filter.apply_filter` 학습 루프에서 ON
- Train/test dynamics 일치 확인
- baseline 성능 기록

### Step 2 — Controller 전환만 (Option B)
- 공유 객체 없이 양 팔 impedance + RL은 EE target 출력
- 출력: 양 팔 EE의 상대 target + EE1의 절대 target
- 환경 변경 적당 수준

### Step 3 — 패러다임 전환 (Option C)
- 공유 막대 추가 + cooperative impedance + object-level RL
- contact force를 state로 활용
- 본격적인 cooperative manipulation 셋업

### Step 4 — Variable Impedance (확장)
- Actor 출력에 stiffness까지 포함: `[x^d_obj, K_obj, K_grip]`
- "좁은 통로에선 단단하게" 같은 행동 학습

## 7. 연구 Narrative 제안

> *"기존 RoboBallet류 접근법은 dual-arm 협응의 기하 제약을 reward shaping으로만 다뤘다.
> 우리는 양 팔이 객체를 공유하는 cooperative manipulation 셋업에서
> contact force / internal wrench를 state로 활용하고,
> cooperative impedance controller 위에 object-level policy를 학습함으로써
> 제약 만족을 reward가 아닌 dynamics에 새겨 넣는다."*

# Cooperative Impedance + Object-level RL 마이그레이션 계획

## 현재 구조의 문제

현재 RL(TD3 + GNN)이 14차원 관절 속도를 직접 출력하면서, 태스크 달성과 기하 제약 유지를 reward shaping으로 동시에 학습하고 있다. 두 팔 사이에 공유 물체가 없어 내력(internal force)이라는 물리량이 존재하지 않으며, force feedback이 의미 있는 제약 위반 신호를 담지 못한다. Fine-tuning을 반복해도 성능 한계에 부딪히는 근본 원인이다.

## 목표 구조

물리가 보장할 수 있는 것(제약 만족, 내력 조절)은 cooperative impedance controller에 맡기고, 판단이 필요한 것(물체를 어디로 옮길지)만 RL에 남긴다.

```
GNN Policy (두뇌)
  입력: 물체 상태, 목표 위치, 장애물, 양팔 상태, contact force
  출력: x_d_obj (6-dim)
          ↓
Cooperative Impedance Controller (근육·반사신경) — 두 팔에 대해 1개
  x_abs, x_rel 분해 → f_abs, f_rel 계산 → f₁, f₂ 분배 → τ₁, τ₂ 변환
          ↓
로봇 모터: set_joint_effort_target(τ₁, τ₂)
```

## Step 2 — Impedance Controller 도입 (공유 물체 없음)

### 목적
RL 출력을 관절 속도 → EE 목표 위치로 전환하고, 임피던스 제어기가 토크를 생성하는 구조로 바꾼다. 공유 물체 없이 controller 전환만 검증한다.

### 변경 사항

#### 환경 설정 (`dual_arm_transport_cfg.py`)
- `ImplicitActuatorCfg`를 effort(torque) 모드로 변경
- action space: 14-dim joint velocity → 12-dim EE target (양팔 각 6-dim)

#### 액션 적용 (`_apply_action`)
```python
def _apply_action(self):
    x_d_1 = self.actions[:, :6]   # 팔1 EE 목표
    x_d_2 = self.actions[:, 6:12]  # 팔2 EE 목표

    # 각 팔 독립 임피던스 (아직 cooperative 아님)
    f_1 = K * (x_d_1 - x_1_curr) - D * x_1_vel
    f_2 = K * (x_d_2 - x_2_curr) - D * x_2_vel

    tau_1 = J_1.T @ f_1 + gravity_comp_1
    tau_2 = J_2.T @ f_2 + gravity_comp_2

    self.robot_1.set_joint_effort_target(tau_1)
    self.robot_2.set_joint_effort_target(tau_2)
```

#### GNN action head
- 출력 차원: 14 → 12
- 각 로봇 노드에서 6-dim EE target 출력

### 확인할 것
- 임피던스 제어기 위에서 RL 학습이 안정적으로 수렴하는지
- Step 1 baseline 대비 성능 비교
- K, D 값의 적절한 초기값 탐색

### 예상 소요
- 코드 변경: 2~3일
- 학습 및 검증: 3~5일

## Step 3 — 공유 물체 + Cooperative Impedance + Object-level RL ⭐

### 목적
두 팔 사이에 공유 물체(rod)를 도입하여 closed kinematic chain을 물리적으로 형성하고, cooperative impedance controller 위에 object-level RL을 올린다. 이것이 핵심 패러다임 전환이다.

### 변경 사항

#### 환경 설정 (`dual_arm_transport_cfg.py`)
- 공유 막대(rod) `RigidObject` 추가
- 양 그리퍼-막대 사이 fixed joint 또는 high friction + closed gripper
- `ContactSensorCfg` 추가 (그리퍼-막대 접촉력 측정)

#### 액션 적용 (`_apply_action`)
```python
def _apply_action(self):
    x_d_obj = self.actions[:, :6]           # 물체 목표 위치 (6-dim)
    w_d_int = self.actions[:, 6:12]         # 원하는 내력 (선택)
    # 또는 w_d_int = default_squeeze_force  # 고정값 사용

    # 현재 물체 상태
    x_obj_curr = self.rod.data.root_pos_w   # 위치
    x_obj_vel = self.rod.data.root_lin_vel_w # 속도

    # Cooperative impedance law
    f_abs = K_abs * (x_d_obj - x_obj_curr) - D_abs * x_obj_vel
    f_rel = w_d_int  # 또는 K_rel * (x_rel - x_rel_d)

    # 양팔 분배
    f_1 = 0.5 * f_abs + f_rel
    f_2 = 0.5 * f_abs - f_rel

    # 관절 토크 변환
    tau_1 = J_1.T @ f_1 + gravity_comp_1
    tau_2 = J_2.T @ f_2 + gravity_comp_2

    self.robot_1.set_joint_effort_target(tau_1)
    self.robot_2.set_joint_effort_target(tau_2)
```

#### 관측 (`_get_observations`)
- 기존 상태 + contact force 추가
- `ContactSensor`에서 그리퍼-막대 접촉력 읽기
- 물체 위치, 속도, 목표까지 거리를 observation에 포함

#### 보상 (`_get_rewards`)
- `r_constraint` → 거의 제거 (물체 강체가 보장)
- `r_object_pose` 추가: 물체가 목표에 가까울수록 보상
- `r_grip` (선택): internal wrench가 적절 범위에 있으면 보상

#### GNN 구조
- 출력 차원: 14 → 6 (또는 12)
- graph에 object 노드 추가, 해당 노드의 출력만 action으로 사용
- contact force를 edge feature 또는 global feature로 주입

### 확인할 것
- Cooperative impedance controller가 Isaac Sim에서 안정적으로 동작하는지
- RL 학습 수렴 속도 (Step 1, 2 대비 개선 기대)
- Contact force가 observation으로 유용한 신호를 제공하는지
- 내력이 안전 범위 내에서 유지되는지

### 예상 소요
- 코드 변경: 1~2주
- 학습 및 검증: 1~2주

## Step 4 — Variable Impedance (논문 확장)

### 목적
GNN이 물체 목표 위치뿐 아니라 임피던스 파라미터(K_abs, K_rel)까지 출력하게 하여, 상황에 따라 강성을 자동 조절하는 지능적 운반을 학습한다.

### 변경 사항

#### GNN 출력 확장
```
기존 (Step 3): x_d_obj (6-dim)
확장 (Step 4): x_d_obj (6-dim) + K_abs (6-dim) + K_rel (6-dim) = 18-dim
```
K값은 항상 양수여야 하므로 softplus 또는 exp 활성화 함수 적용.

#### 상황별 기대 행동
- 넓은 공간: K_abs를 낮춰서 부드럽게 이동 (외란에 유연하게 대응)
- 좁은 통로: K_abs를 높여서 궤적을 정밀하게 추종 (벽 충돌 방지)
- 물체 내려놓기: K_rel을 점진적으로 낮춰서 부드럽게 release
- 무거운 물체: K_abs를 높여서 처짐 방지

#### 보상 설계
- 기존 보상 + K값 변화에 대한 smoothness penalty (급격한 K 변화 방지)
- 에너지 효율 보상 (불필요하게 높은 K 사용 시 벌점)

### 확인할 것
- RL이 실제로 상황에 따라 다른 K값을 학습하는지
- Step 3 고정 K 대비 성능 개선이 있는지
- K값의 변화 패턴이 물리적으로 해석 가능한지

### 논문 스토리
> "기존 cooperative manipulation 접근법은 임피던스 파라미터를 사전에 고정했다.
> 본 연구는 GNN 기반 정책이 물체 목표와 함께 임피던스 파라미터를 상황 적응적으로
> 출력하도록 학습함으로써, 다양한 환경 조건에서 안전성과 효율성을 동시에 달성한다."

### 예상 소요
- 코드 변경: 3~5일 (Step 3 기반 확장)
- 학습 및 검증: 1~2주
- 분석 및 시각화: 1주

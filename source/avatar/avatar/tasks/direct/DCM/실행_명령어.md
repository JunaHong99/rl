## 2. 학습 (train)

> 학습은 대부분이 **검증 레시피 값(기본값과 다름)**이라 못 뺌. 뺄 수 있는 건 `--num_rounds`(--use_mlp면 무시) + base 범위(기본값)뿐. 나머지(num_envs/total_steps/warmup/buffer/batch/updates/alpha/k_future/her_weight/max_obstacles)는 기본값과 달라 **필수**.

### 검증된 baseline (고정 base, 89.5%)
```bash
CUDA_VISIBLE_DEVICES=0 python train_phase3_sac.py --headless --num_envs 8192 --total_steps 30000000 --warmup_steps 700000 --buffer_size 3000000 --batch_size 2048 --updates_per_step 24 --no-auto_alpha --fixed_alpha 0.1 --use_her --k_future 1 --her_progress_weight 100 --no_rod_filter --max_active_obstacles 0 --leader_follower --lf_dense_progress --use_kin_graph --vary_grasp --same_side --no_gravity --use_mlp
```

### 베이스 랜덤화 (간격 0.8~1.4m, yaw ±15°)
```bash
CUDA_VISIBLE_DEVICES=0 python train_phase3_sac.py --headless --num_envs 4096 --total_steps 30000000 --warmup_steps 700000 --buffer_size 3000000 --batch_size 2048 --updates_per_step 24 --no-auto_alpha --fixed_alpha 0.1 --use_her --k_future 1 --her_progress_weight 100 --no_rod_filter --max_active_obstacles 0 --leader_follower --lf_dense_progress --use_kin_graph --vary_grasp --no_gravity --use_mlp --randomize_base
```
- **`--num_envs 4096`**: 8192는 `replicate_physics=False`(vary_grasp/randomize_base가 강제)로 씬 빌드 시 RAM 폭식 → OOM/hang. 4096 권장.
- **`--same_side` 뺌**: base yaw가 돌면 same_side 의미 약함 + 캐시 생성 2h→40min.
- **`--randomize_base`만**: 범위 기본값(0.8/1.4/±15°). 다른 범위 쓰려면 `--base_spacing_min/max --base_yaw_range` 명시.
- 첫 실행은 새 `_basevar` pose 캐시 생성(one-time, ~40min). 이후 재사용.

## 3. 평가 (eval_lf) — 성공률 + 버킷별 + IK/특이점 + 진동 진단

```bash
export LD_LIBRARY_PATH=<isaaclab conda env>/lib:$LD_LIBRARY_PATH
CUDA_VISIBLE_DEVICES=0 python -u eval_lf.py --model_path logs/phase3_sac_20260804-074011/model_final.pt \
    --leader_follower --use_kin_graph --vary_grasp --no_gravity --randomize_base --num_envs 512 --headless
```
- **뺀 플래그(다 기본값)**: `--num_rounds 8`(KinMLP는 무시), `--base_spacing_min/max`, `--base_yaw_range`. → `--randomize_base`만으로 학습과 같은 분포(0.8~1.4m, ±15°).
- **학습 조건과 일치**시켜야 유의미. 고정 base 모델은 `--randomize_base` 빼고 `--same_side` 추가.
- 유용한 옵션: `--lf_ik_iters 50`(IK 정밀도 진단), `--grasp_preset heldout.pt`(held-out 파지), `--stochastic`, `--num_envs 1024`(에피소드 2배).

## 4. 녹화 (record_lf) — mp4 영상

```bash
export LD_LIBRARY_PATH=<isaaclab conda env>/lib:$LD_LIBRARY_PATH
python -u record_lf.py --model_path logs/phase3_sac_20260804-074011/model_final.pt \
    --headless --enable_cameras --device cuda:0 \
    --use_kin_graph --vary_grasp --no_gravity --randomize_base --n_clips 8 --out basevar_replay.mp4
```
- **뺀 플래그(기본값/자동)**: `--num_rounds`(KinMLP 무시), base 범위(기본값), `--leader_follower`(record는 항상 ON), `--use_mlp`(체크포인트로 KinMLP 자동판별).
- ⚠️ **`--enable_cameras` 필수**, GPU는 `--device cuda:0` (렌더링엔 `CUDA_VISIBLE_DEVICES` 쓰면 GLX 크래시).
- 결과 `basevar_replay.mp4` → `scp`로 받아 재생.

## 6. 진동 진단 판독 (eval_lf 출력)

- **액션flip**: 리더 출력(Δq) 방향 반전율. 실패에서 ↑ = H1(네트워크 출력 진동).
- **rot_err flip / pos_err flip**: rod 오차 진동율. 액션flip 낮은데 이게 ↑ = H2(팔로워 협응 진동).
- base-var 모델(2026-08-04) 결과: 실패=성공 액션flip 동일(0.27)인데 **rot_err flip 0.17→0.50** → **H2 확정**(리더는 매끄러운데 rod 회전이 협응으로 진동).

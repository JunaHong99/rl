# 연구 진행 정리 (6월 5~9일)

## 한 줄 요약

> Dual-arm rod transport 학습이 65% ceiling에서 정체된 원인이 **정책이 아니라 시뮬레이션 환경의 reset transient** 였음을 밝혔고, 환경을 깨끗하게 만든 뒤 재학습으로 ceiling을 73%까지 올림. 100%까지 가는 구조적 경로도 확인됨.

---

## 1. 문제 설정

**Task**: Franka 2대가 fixed joint로 묶인 rod를 random goal pose까지 옮긴다.

**기존 상태**:
- SAC + MLP policy, 30회 plateau 끝에 18M ckpt에서 65% success 보고
- 그러나 plateau가 정책 한계인지, 환경 한계인지, 평가 측정 한계인지 불명확
- 메모리에는 "84% 달성"으로 기록되어 있었지만 재현 안 됨

**핵심 의문**:
> 65%가 정책의 진짜 ceiling인가? 그렇지 않다면 무엇이 ceiling을 만들고 있는가?

---

## 2. 조사 단계

### Stage A — 측정의 신뢰성부터

"84%" 메모리가 재현 안 되니 평가 자체를 의심.
TF 로그 raw 추출 → **실제 peak는 10M에서 70%** (memory 84% 근거 없음). 18M 이후 정체/퇴행.
또 eval 코드에 success 카운팅 버그 발견 — auto-reset이 success flag 지워서 0%로 보고됨.

**Takeaway**: "기존 결과가 X였다"는 주장도 검증해야 함. 측정이 망가져 있으면 위에 쌓인 분석 전부 무의미.

### Stage B — 한계의 출처: 정책인가 환경인가

정책을 우회하고 **controller를 단독 검증**.
- Target = goal 직접 (정책 우회) → 도달율 **51.5%**
- 5cm step 명령 → peak 656mm 폭주, 수렴 0
- 1cm 명령에도 800mm 폭주

→ **Controller 단독으로 task 절반밖에 못 풀고 있었음**. 정책 65%는 그 위에서 +14%p 끌어올린 결과 = 정책이 controller 한계를 학습으로 보상하고 있던 것.

**Takeaway**: RL plateau 디버깅에서 환경/controller가 먼저 의심받아야 함. 정책은 환경이 표현해주는 만큼만 학습 가능.

### Stage C — 진짜 원인 추적

Controller 폭주의 후보 가설들을 차례로 검증:

| 가설 | 결론 |
|---|---|
| Per-arm impedance가 closed-chain에서 force fight → cooperative가 답 | **부정**. cooperative가 오히려 더 나쁨 (도달율 41% vs per-arm 51.5%) |
| Jacobian singularity / joint limit | **부정**. stable/unstable 그룹 간 차이 없음 |
| Reset 시 fixed-joint snap이 운동에너지 주입 | **확정**. unstable 그룹은 settle 후에도 ω 3배, v 2배 |

**Takeaway**: 가설을 한 번씩 코드로 깨야지, 직관으로 뛰어넘으면 안 됨. "cooperative가 답"이라는 그럴듯한 가설이 실제로는 틀렸음.

### Stage D — 처방과 검증

Reset transient를 흡수하는 settle phase 도입.

| 설정 | Unstable% |
|---|---|
| Baseline (settle 없음) | 9-11% |
| Settle 10 step | 10.9% |
| **Settle 30 step** | **3.9%** |

→ env3에 빌트인 (`SETTLE_STEPS_AT_RESET = 30`).
→ HER buffer와 train script에 settle mask 추가 (정책이 "아무것도 안 하기"를 학습하지 않도록).

### Stage E — 재학습으로 효과 측정

같은 10M training budget, 같은 policy architecture로 fresh 학습:

| 모델 | Deterministic eval success |
|---|---|
| 옛 18M (no settle) | 65.5% |
| **새 10M (env3 settle)** | **72.9%** (+7.4%p) |

같은 컴퓨팅에 정책 7.4%p 향상. **Ceiling이 옮겨졌음**.

추가 발견: success 판정 자체가 conservative였음 (env3 dones는 episode 마지막 step만 봄 → "도달했다 떠난" 케이스 누락). reward function 의도에 맞춰 재정의 → **73%는 underestimate, 더 높을 가능성**.

## 3. 거시적 정리

### 무엇이 진짜 ceiling이었나

```
이전 인식:           실제:
                                  ┌────────────────────────┐
정책이 65%까지 학습  →  환경이    │ Reset transient ~10% noise │ 만들고
                                  └────────────────────────┘
                       정책은     ┌────────────────────────┐
                                  │ 나머지 90% 안에서 학습 │ 함
                                  └────────────────────────┘
```

플라토는 정책 한계가 아니라 **데이터의 10%가 학습 불가능한 노이즈**여서 발생.

### Controller / 정책 / Sampler의 분할

이번 디버깅 끝에 명확해진 책임 분할:

| 컴포넌트 | 역할 | 현재 상태 |
|---|---|---|
| Sampler | 초기 자세 분포 생성 | ~5% tail이 joint limit 근처 → 구조적 불안정 케이스. 필터링 필요 |
| Controller | rod target → joint torque | Reset 후 settle 30 step 받으면 안정. settle 없으면 ~10% 폭주 |
| Policy | rod target delta 생성 | 65→73% 향상 확인. 더 학습하면 더 오를 여지 (effective data 절반) |

→ 각 컴포넌트가 얼마나 ceiling을 만드는지 분리해서 측정 가능해짐.

### 정책 입장의 의미

정책은 처음부터 다음을 해결해야 했음:
1. Goal 방향으로 rod 이끌기 (본 task)
2. Reset transient를 자기 action으로 보상하기 (이전 환경)
3. Controller의 ~30mm tracking lag를 안고 도달 판정 받기

이번에 (2)를 환경에서 흡수시켜 정책 학습 부담을 줄였음. 그래서 73%로 향상.
(3)이 다음 ceiling 후보. (1)은 정책의 본질적 학습.

## 4. 현재 위치와 100%까지의 경로

```
65% ─[settle + 재학습]─→ 73% ─[sampler filter]─→ ~80%(예상) ─[추가 학습]─→ ?
                                ~5% structural               effective data 회수
                                unstable 제거                (settle mask로 절반)
```

### 남은 ceiling 후보 (우선순위)

1. **Sampler tail (~5%)** — joint margin < 0.2 rad 케이스. 구조적으로 폭주. reject sampling 추가 시 즉시 제거 가능. cache 재생 ~10분.

2. **Effective RL data 절반** — settle mask로 buffer push가 RL step만 되니 같은 total_steps 라도 학습량 절반. 추가 학습이 의미 있음.

3. **Controller residual tracking error ~24mm** — settle 후 안정 상태에서도 30mm 안팎의 tracking lag. 정책이 이 위에서 20mm 도달 판정을 받으려면 빠듯함. impedance gain 튜닝이나 target smoothing으로 줄일 수 있을지.

4. **Success 판정 정의** — env3 reward는 (pos AND rot), dones는 (pos만). 일관성 확보 필요. 정의 통일하면 측정치 자체가 변함.

## 5. 방법론적 교훈

- **메모리/기록 검증**: "이전에 X였다"는 주장도 raw data로 재현 가능해야 신뢰. 4일 전 메모리도 stale일 수 있음.

- **측정의 우선순위**: 평가 코드 자체에 버그가 있으면 그 위 모든 분석이 거짓. eval_mlp.py에서 두 번이나 success 판정 버그를 발견했음 (`reached_once` 자동 reset, `terminated`의 final-step-only).

- **단위 일관성**: test 스크립트 한 줄 (`D = P` 단위 변환 빠짐)이 PASS verdict까지 거짓 보고로 만듦. 분석 결과를 의심하기 전에 단위부터 확인.

- **컴포넌트 분리 검증**: 정책을 우회하고 controller만, sampler만 단독으로 테스트할 수 있어야 ceiling의 위치를 정확히 짚을 수 있음.

- **그럴듯한 가설을 깨는 비용**: "cooperative impedance가 답"이라는 가설이 직관적으로 맞아 보였지만 실제 실험으로 부정됨. 실험 비용 < 잘못된 처방으로 며칠 보내는 비용.

- **mean보다 per-env 분포**: 평균 14mm인데 max 805mm 같은 분포에서 진짜 문제 (소수의 폭주 envs)가 보임. mean만 보면 못 잡음.
